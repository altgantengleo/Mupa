## 2. Audit Stabilitas, Memori, Lifecycle & Perbaikan (Checkpoint R5)

| # | Area Audit | Temuan | Perbaikan yang Diterapkan | Status |
|---|---|---|---|---|
| **S1** | **StrictMode (Debug)** | Belum ada `StrictMode` di debug build untuk mendeteksi I/O disk/jaringan di main thread atau kebocoran `Closeable`/SQLite/Activity. | Menambahkan `enableDebugStrictMode()` (ThreadPolicy + VmPolicy `penaltyLog`) di `MupaApplication.onCreate()` yang **hanya aktif saat `BuildConfig.DEBUG`**. | Diperbaiki |
| **S2** | **Memori Gambar Coil 3 & LeakCanary** | Belum ada konfigurasi batas memori/disk `SingletonImageLoader.Factory` sehingga cache bitmap bisa membengkak di perangkat RAM rendah; `MupaCinemaOverlay` sebelumnya membuat `ImageLoader(context)` baru setiap kali lagu berubah. | `MupaApplication` mengimplementasikan `SingletonImageLoader.Factory` (MemoryCache 20% RAM / 12% pada `isLowRamDevice`, DiskCache 64 MB) dan membersihkan memory cache pada `onTrimMemory(TRIM_MEMORY_BACKGROUND)`. `MupaCinemaOverlay` memakai `SingletonImageLoader.get(context)`. LeakCanary `2.14` terpasang sebagai `debugImplementation`. | Diperbaiki |
| **S3** | **Lifecycle `MediaController` Race Condition** | Jika `MupaPlayerViewModel.onCleared()` terpanggil sebelum `MediaController.buildAsync()` selesai resolve, callback listener yang terlambat berpotensi mengikat `playerListener` ke controller yang bocor. | Menambahkan flag `@Volatile private var isCleared = false` di `MupaPlayerViewModel`; callback future langsung merilis controller jika `isCleared == true`, dan `onCleared()` membersihkan `pendingCommand`, jobs, listener, serta `MediaController.releaseFuture()`. | Diperbaiki |
| **S4** | **Foreground Service `onTaskRemoved`** | `MupaPlaybackService` belum meng-override `onTaskRemoved()` sehingga jika aplikasi digeser dari Recents saat sedang jeda/idle, service bisa tetap menggantung. | Menambahkan `override fun onTaskRemoved(rootIntent: Intent?)` di `MupaPlaybackService` yang memanggil `stopSelf()` bila `!playWhenReady || mediaItemCount == 0 || STATE_ENDED`, sementara pemutaran aktif tetap berjalan di latar belakang. | Diperbaiki |
| **S5** | **Kesesuaian Coroutine & Lifecycle Compose** | Audit rekursif seluruh `app/src/main` & `playback/src/main`: **0** pemakaian `GlobalScope`, **0** pemakaian `collectAsState()` mentah (seluruh layar memakai `collectAsStateWithLifecycle()`), dan satu-satunya `runBlocking(Dispatchers.IO)` berada di `MupaPlaybackService.resolveDataSpec()` pada thread loader latar belakang ExoPlayer (bukan main thread). | Terverifikasi bersih; dicatat agar tidak memindahkan `resolveDataSpec` ke main thread. | Terverifikasi |
| **S6** | **Visual Clipping Lirik & Cinema (Temuan Inspeksi PNG R3)** | Inspeksi langsung screenshot `r3_now_playing_lyrics_360dp.png` dan `r3_cinema_360dp.png` menemukan baris lirik bawah terpotong keras di panel inline dan bertabrakan dengan seekbar di Cinema saat kontrol tampil. | Menambahkan gradien fade tepi atas/bawah tanpa `Offscreen` layer penuh pada `MupaInlineLyricsPanel` & `MupaCinemaOverlay`, serta menaikkan padding bawah lirik Cinema dari `128dp` menjadi `168dp`. Diverifikasi ulang langsung pada PNG baru. | Diperbaiki |
| **S7** | **File Lokal Hilang / Izin SAF Dicabut** | Jika file lokal dihapus dari File Manager atau izin URI SAF dicabut, pemutaran bisa gagal diam-diam atau crash. | `MupaPlayerViewModel` memeriksa `localLibraryRepository.isUriReadable(uri)` saat restore & play, dan `onPlayerError()` menampilkan pesan jelas lalu melakukan skip aman ke trek berikutnya bila antrean > 1 lagu. | Diperbaiki |
